# UX Lab 可用性测试主持指南

> 第二阶段 B1：可交互浏览器研究原型已实现，**不代表正式业务功能已实现**。尚未招募或测试真实参与者，没有用户结论或效果指标。自动化浏览器检查是工程验证，不是用户研究。

## 1. 原型入口、边界和准备

开发：`npm ci`、`npm run dev`，在本机访问 `/ux-lab`；远程使用平台支持的端口转发。研究者与参与者需能看到页面上的“研究原型”说明。

| 实验 | 路径 | 本版实现 | 对应原设计 |
| --- | --- | --- | --- |
| E1 A | `/ux-lab/e1/a` | 手动输入 → 编辑 → 预览 → 确认私人保存 | M |
| E1 B | `/ux-lab/e1/b` | 输入 → 固定脚本 → 选消息 → 固定候选 → 编辑/确认保存 | D |
| E2 A | `/ux-lab/e2/a` | 自愿开启建议 → 固定回复后自动弹窗 → 查看/忽略 | A |
| E2 B | `/ux-lab/e2/b` | 同条件 → 消息下非模态提示 → 查看/忽略 | B |
| E2 C | `/ux-lab/e2/c` | 选消息 → 主动整理 → 编辑/放弃/确认 | C |
| E3 A | `/ux-lab/e3/a` | 日期/关键词筛选、时间线与来源详情 | T |
| E3 B | `/ux-lab/e3/b` | 可选主题、同样筛选与来源详情 | G |
| E3 C | `/ux-lab/e3/c` | 选虚构范围、同意单次模拟处理、固定故事、逐条来源 | S |

准备步骤：核对原型版本 `b1.1`；选定设备与顺序；默认 E1/E2 全用 X“第一次主持会议”，E3 全用 `review-set-1` 的 12 条样例；展开研究员工具、确认任务与素材；先试跑失败/重试与清空流程，再正式比较。开启故障演练的任务不得与正常任务混合汇总。

本次要求方案使用相同材料，因此本版没有实现原 [实验方案](UX_EXPERIMENTS.md) 中三套平衡回顾材料。E1/E2 可切换共同的 X/Y，但同一对照必须选择一致素材。重复材料可能让后面的方案看起来更快；轮换顺序只能降低、不能消除学习效应。当前只能探索过程问题，不能直接计算真实提升率。若进入正式比较，再补等难度材料与试跑版本，不悄悄沿用原门槛。

所有模拟“保存”只在当前方案页面内存中，离开/刷新/重置丢失，不进 localStorage，不与 `/journal` 或 `/memories` 共享。没有网络 AI、数据库或正式数据采集。角色图标沿用项目中的 Lucide 图标，不使用第三方角色美术。

## 2. 参与者知情同意（主持人逐项说明）

“我们测试的是产品方案，不是你的能力。所有生活事件是虚构样例；不要输入姓名、电话、真实聊天或私人经历。角色回复、候选和故事是预先编写的脚本，不是真实 AI，也不能处理你自己的故事。你可以随时暂停、退出或要求删除研究记录，拒绝任何问题不会带来处罚。”

“如果你同意，研究员会在你开始任务时开启本浏览器内的匿名计时和操作计数，在结束后记录完成类别与评分。这些记录不含正文、搜索词、IP 或联系方式，不自动上传。可明确保存到这个浏览器或下载文件；使用随机会话编号，不输入你的姓名。研究同意不等于让 AI 长期记住。”

“如果另外录屏、录音或引用你的反馈，需要另行征得同意；此网页不做这些采集。计划录屏最长 30 天、去标识摘要最长 90 天，与 [研究计划](USER_RESEARCH.md) 一致。主持人需落实受限保存位置、负责人和删除日期；未落实前不开始外部研究。”

确认理解后，由研究员勾选“已说明研究性质并取得匿名计时与计数同意”。拒绝计时者仍可体验；只观察、不点击开始、不产生匿名结果。退出时可“撤回研究同意并清空”；已下载文件需研究员另行删除。不要把虚构授权面板的确认当研究录音许可。

## 3. 顺序与主持纪律

先 E1，再 E2，再 E3，可分两次会话。按 [研究计划](USER_RESEARCH.md) 计划先 2 位试跑、再 6 位探索；这里不是已有参与人数。试跑结果与正式探索分开。

| 顺序编号（不输入真实身份） | E1 | E2 | E3 |
| --- | --- | --- | --- |
| 1 | AB | ABC | ABC |
| 2 | BA | ACB | ACB |
| 3 | AB | BAC | BAC |
| 4 | BA | BCA | BCA |
| 5 | AB | CAB | CAB |
| 6 | BA | CBA | CBA |

主持人只读任务，不说“推荐你点击轻提示”。先观察独立完成，确需帮助时记录协助且最终选“协助完成”。可要求轻声说出正在想什么，但它会影响耗时；所有任务采用同一口径并注明使用了思考出声。

开始计时会重置当前原型，防止预先完成。正式任务先点击开始，再读完整任务（或统一读完再开始，研究负责人冻结口径）；时间包含输入、固定 3 秒等待、阅读、校对和保存。休息时暂停计时，并请参与者暂停操作。暂停不冻结界面，但期间不计时、不计操作。

任务后人工判定结果、询问评分再结束：若评分问答算进时间将污染结果，**到达成果时立即暂停计时**，完成评分再“结束并记录任务”。未达成果也在终止时暂停，再选择失败/超时/取消。弹窗建议忽略后的体验应先观察后评分，不抢先解释权限。

## 4. E1：记录方式

主持话术：“把这段虚构材料保存为你以后能找回的私人记录，不让角色长期记住。可以编辑，但不要补没有给出的事实。请用这个方案完成。”

X 正确事实：2026-04-12、第一次独立主持项目会议、公司会议室；没有给出焦虑或其他感受。Y：2026-04-19、和朋友河边散步、下次带相机；没有具体几点。

A 标题可空，日期和正文必须有。B 必须输入内容，固定脚本等待 3 秒；它不理解输入，候选只来自共同素材。不要把“能理解任意输入”作为本轮判断对象。校对后的私人暂存状态应明确为未授权。

完成标准：最终日期/正文正确且研究记录已暂存、长期记忆未授权。标题措辞不作强制要求。总限时 180 秒；辅助、事实错误、超时分别记录。界面不自动判断事实正确，记录了错误日期也不能判独立成功。

任务后问：“哪一步最费力？用了多少组织或检查的思考（1–7）？如果额外等待 10 秒，还愿意用吗？”额外延迟只是问题，不冒充真实 API 性能结果。

## 5. E2：保存时机与边界

每方案都测试“继续聊天，不保存”和“只私人保存”，两轮之间结束任务并重新开始，以免带入提示已忽略状态。A/B 如要观察提示，任务明确允许参与者自愿开启本会话建议；默认关闭不能被研究员偷偷打开。C 没有自动分析建议，但相同主动整理路径始终可用。

任务一：“聊聊这段虚构事件，你还想继续聊，暂时不想留下记录。”正确结果：忽略/关闭弹窗或卡片，或 C 选择暂不整理，私人记录仍为空；可继续发送消息，无再次自动提示。

任务二：“把刚才的片刻保存给自己，但不让小栖以后记住。”正确结果：查看/主动进入候选、可编辑、预览、确认私人保存，角色状态未授权。查看或关闭提示不能造成保存。每轮限时参考 120 秒。

复述题先问再解释：“内容保存在哪？角色以后能用吗？撤回授权后原记录还在吗？已经发出的回复会消失吗？”正确答案：当前原型页面内存；未独立授权不算角色记忆；撤回保留私人记录；不能收回已发内容。真实产品将来是私人记录库，与这里的暂存不同，应明确分开。

管理微任务可另选“保存、授权、撤回，再删除”：

1. 保存后 10 秒内撤销，确认研究记录消失；错过时仍能从详情删除。
2. 重新保存，10 秒窗口结束后另开长期授权面板，先取消一次，再确认授权。
3. 撤回角色授权，确认私人记录仍在。
4. 删除私人记录，确认关联模拟授权也消失；另可编辑记录验证旧授权失效。

微任务每步参考 90 秒，主持人另记各步时间；网页管理任务整体参考 360 秒，只导出总时间，不能当每步耗时。研究员不要用工具加速 10 秒窗口。授权用途、角色和确切文本应可见，默认不授权。

评分：“刚才的提示有多打扰，1 完全不打扰至 5 非常打扰？是否中断你正在做的事？”可发现性与隐私理解先于保存率。

## 6. E3：找回有用的来源

所有方案共享 12 条虚构记录。故事方案先选择全部 12 条并确认模拟本次处理，保留用户主动决定范围的操作成本，不授权长期记忆。

三轮检索任务，每轮重新开始、限时 90 秒：

| 任务 | 话术 | 人工正确结果 |
| --- | --- | --- |
| 日期线索 | “找到四月第二周首次主持项目会议的记录，告诉我地点。” | 打开 r04 来源，指出公司会议室 |
| 主题线索 | “找到朋友建议下次带相机的散步，告诉我约定。” | 打开 r07 来源，指出下次带相机 |
| 不存在 | “查找学会潜水那天，如果没有记录请说明。” | 在指定完整范围内查找，无匹配并确认未找到；不能拿类似故事当答案 |

故事卡每条事实有来源按钮，必须打开原记录；只复述故事文字不算成功。网页的“标记为找到的来源”只是进展标记，研究员必须核对是不是目标 ID 和字段。“未找到”需确认正确范围与筛选，不是随意缩小范围后的零结果。

反馈：“你凭什么相信这是那次经历？如果不记得日期怎么找？这张故事卡比原文增加了什么有用价值？”评分不取代来源成功。

## 7. 错误、取消与恢复演练

正式比较默认无故障。另起演练任务，研究员工具可选择下一次回复、保存、授权/撤回或故事播放失败；选择只消费一次。没有服务端故障被伪装成真实 API。回顾 A/B 没有生成操作，用日期范围错误/无结果来测试恢复。

- 空正文预览 → 明确错误 → 修正 → 重试。
- 回复失败或停止 → 输入保留 → 重发；也可降级手写。
- 保存失败 → 仍未保存、草稿保留 → 重试；提交中可取消。
- 候选放弃 → 不保存 → 从消息重新进入。
- 授权/撤回失败 → 状态不改变 → 重试或取消。
- 故事播放失败/停止 → 选定范围保留、无输出 → 重试；取消后需重新确认单次处理。
- 日期范围颠倒 → 错误 → 修正；无匹配 → 清筛选。

消费的故障会将匿名任务标为 `faultInjected: true`，不得混入正常体验效果比较。刷新或返回目录会丢弃原型状态；结束任务后再离开。计时中目录返回被提示阻止；浏览器关闭/刷新有离开提示，强制关闭将丢失未结束计时。计时中正式顶部导航和其他页面链接也会被提示阻止，需先结束再离开；浏览器历史返回/强制关闭仍可能绕过链接保护，未结束任务不会保存或上传。

## 8. 匿名记录：实际采集口径

没有自动开启、没有全站监听、没有外部 analytics。仅 UX Lab 原型交互区在计时中记录聚合计数，不保存逐事件原文。研究员工具的操作不计入参与者点击；弹窗操作属于原型，计入。

| 字段 | 含义 / 局限 |
| --- | --- |
| sessionId / runId | 浏览器随机编号，不是姓名；同会话多任务，不等于多个参与者 |
| prototypeVersion / experiment / variant / materialId / taskId | 可复核方案、素材与次序（结果数组顺序），无内容正文 |
| elapsedMs / pausedMs | 单调时钟计时，包含模拟等待；暂停排除，后置问答应先暂停 |
| clicks / focusChanges | 自动统计原型区点击事件和获得焦点次数，不等于完整操作步骤；滚动/返回等由人工观察 |
| inputEvents / enteredCharacters | 输入事件及浏览器提供 data 的字符数量，不含文字；填充、删除、输入法等可能不提供 data，不能当总字数/按键数 |
| errors | 自动校验/模拟失败加研究员手工标记次数；同一错误不要重复手标 |
| evidence / sourceId | 最后界面进展与白名单虚构来源 ID，不自动判断正确；中间动作需人工观察 |
| outcome | 研究员判定独立、协助、失败、取消、超时，不默认成功 |
| disturbance / cognitiveLoad | 人工选择评分，未问为 null，不自动填零 |
| understanding / severity / category | 人工分类，未测保留 unassessed/none |
| faultInjected | 此任务是否消费故障演练，正式比较须排除 |

默认结果只在内存，刷新丢失。完成任务后可在底部“匿名任务记录”明确保存到 `memonest.uxlab.anonymous-results.v1` 或下载 JSON；载入只恢复白名单元数据，未知字段不会导出，旧版本/损坏数据拒绝。浏览器拒绝存储会报告失败，不声称已保存。

每位参与者结束后，可先导出，再点“新的匿名会话”清原型并重新取得同意；已结束任务结果仍在。退出/共享设备时“撤回研究同意并清空”删除内存与该命名空间存档并重置原型，已下载文件由负责人删除。导出文件不提交到 Git、不放公共作品集；即使无正文也遵守研究资料管理。

## 10. 严重性、迭代优先级与结论边界

- S0：误解保存与长期授权、无法撤回、原型数据混入正式页面或导出正文。停止真实数据研究，修复后优先复测，不能被平均满意度抵消。
- S1：核心保存/找回阻断、错误反馈让用户误以为成功。优先修流程与恢复路径。
- S2：可完成但明显费力、找不到入口、重复确认。按出现次数与任务影响排序。
- S3：文字、外观偏好。仅在不损害可读性和核心任务时迭代。

证据包括失败与反例；结果按真实分母报告，不用软件测试的通过数替代参与人数。对照门槛见 [UX 实验](UX_EXPERIMENTS.md)，但需先补齐该门槛所需的样本、材料平衡和实际研究条件。本版只是可执行探索工具，不宣称哪种方式降低成本或提升留存。
