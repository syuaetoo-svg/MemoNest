# MemoNest｜精简产品需求与决策

更新：2026-10-12。复用既有产品假设与交互决策，按当前实现收敛；不新增功能。真实验收范围见 [README](../README.md)，详细流程见 [USER_FLOW](USER_FLOW.md)。

## 1. 定位与用户问题

以原创 AI 伙伴小栖为表达入口，将用户愿意留下的片刻整理成私人记录，再由用户决定是否授权记忆和发起回顾。手动记录与聊天路径并行。

目标用户是假设的成年学生和初入职场者：希望保留日常，但组织长文、归档和找回内容可能增加负担。没有真实访谈、市场规模或付费意愿证据。

| 假设 | 当前设计回应 | 待验证问题 |
| --- | --- | --- |
| 空白页组织语言增加负担 | 对话后主动选原话，生成可编辑候选 | 包含聊天、校对的总耗时是否优于手写？ |
| 保存容易被误解为 AI 永久记住 | 私人保存、单次处理、长期授权分开 | 用户能否正确复述范围和撤回后果？ |
| 生成回顾未必帮助找回经历 | 时间线、关键词、逐字引用和来源跳转 | 是否找到正确记录，而不只是喜欢文案？ |

## 2. 已实现范围

正常登录；私人记录创建、检索、编辑、删除；原创小栖聊天；主动选用户原话整理候选；精确摘要授权/撤回；选定最多 8 篇记录的阶段回顾。旧单篇回顾保留独立接口。

没有自动保存、自动长期授权、多角色、社交广场、流式聊天、后台周报、默认全量记忆或模型数据库工具。聊天只在当前页面临时保留；UX Lab 的保存建议方案仅供研究，不是正式默认行为。

## 3. 核心设计取舍

| 决策 | 目的与代价 |
| --- | --- |
| 保留手写入口 | 不强制用户为保存先聊天；AI 增益有待验证 |
| 只主动整理选中的用户原话 | 避免 AI 猜测成为生活事实；发现率需另行评估 |
| 日期由用户确认 | 避免模型猜错相对日期；增加一次确认 |
| 临时、非流式聊天 | 在展示前核对来源；不承诺历史恢复或完整指代能力 |
| 记录与记忆分开 | 记录可保留而角色不能调用；增加一次明确授权动作 |
| 关键词检索授权摘要 | 可解释且范围可控；可能漏召回，不宣称语义检索 |

## 4. 验收规则

| 用户任务 | 必须满足的行为 |
| --- | --- |
| 直接记录 | 不依赖 AI；服务端确认后才展示保存成功 |
| 聊天整理 | 候选有原话依据、可修改或放弃；确认前不写记录 |
| 私人保存 | 默认不授权；失败保留当前草稿，同一幂等键重试不重复写入 |
| 授权与撤回 | 确认具体摘要/角色/版本；撤回保留私人记录，后续召回排除旧授权 |
| 编辑或删除来源 | 旧记忆失效；生成中发现变化时丢弃结果 |
| 阶段回顾 | 限本次所选记录与许可；引用可核对，不扩大范围或自动保存 |
| 账号与异常 | 越权被拒绝；取消、超时、错误输出不假报成功；不记录敏感正文日志 |

这些规则由工程测试和本地功能验收提供不同层次的证据；不能用 isolated PGlite 或 mock 证明托管双账号验收完成。

## 5. 隐私边界

私人保存只服务本人管理；单次 AI 处理把所选数据发送给模型服务商；长期授权只覆盖用户确认的摘要和版本。三者不能互相隐式授予。

AI 不执行保存或授权工具；权限由服务端与数据库执行。`store:false` 不代表服务商零保留；撤回不追回已经传输或展示的内容。原文匹配校验不是语义无幻觉保证。

## 6. 指标口径与证据

| 拟评估指标 | 定义与用途 |
| --- | --- |
| 正确记录任务完成 | 完成事实校对、日期确认和私人保存，比较手写与聊天总时间 |
| 权限理解 | 正确复述三种许可及撤回/删除差异；严重误解优先修正文案 |
| 找回任务完成 | 找到指定真实来源，记录耗时和误点击 |
| 生成事实支持性 | 用虚构评测集逐项核对事实、引用与漏项，不用文案满意度替代 |

以上是设计口径，没有实测参与人数、准确率、增长、留存或转化数字。已有本地核心流程成功；真实用户研究、正式埋点、生产部署和完整安全验收仍待开展。

## 7. 交付与停止规则

当前只整理代码已有能力的文档和安全截图，不增加产品功能。功能或工程验证失败不得声称完成；正式对外服务需独立确认部署、账号隔离、服务商数据政策、限额与实机体验。
