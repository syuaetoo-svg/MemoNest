# 单篇日记 AI 回顾：当前实现与验收边界

## 产品决策

优先实现用户主动选择单篇日记的回顾，而非开放角色聊天。日记已经有真实保存、来源版本和用户归属，可在不新增聊天存储、候选抽取、检索或数据库结构的情况下，验证“AI 能否帮助用户重新看见已有经历”。它对应 [AI 工作流](AI_WORKFLOW.md) 中独立的单次处理许可，不扩大长期记忆授权。

目标不是自动撰写人生故事，而是从本篇整理最多三个有原文依据的片刻。角色聊天仍未开放；既有 UX Lab 的固定故事样例继续明确标为研究素材，与本功能隔离。

## 实际操作

登录 → 保存/打开日记详情 → 阅读处理范围与供应商说明 → 主动勾选本次许可 → 请求回顾 → 对照逐段原文引用 → 清除或离开。默认不勾选；每次成功、失败或取消后都需重新确认。回顾只保存在当前组件内，刷新、编辑、退出或清除后丢弃，没有“自动保存到日记/角色记忆”的按钮。

失败不改变私人正文：未配置模型、服务不可用、429、超时、非法结构、引用找不到原文、来源版本改变或已删除，均返回明确错误。重试是用户动作，没有后台自动重试。停止会取消浏览器请求并丢弃迟到结果；已发送的内容不能收回，不保证供应商一定停止处理或收费。

## 配置（尚缺真实 Key）

在自己控制的 OpenAI 项目中配置可用模型和预算，将 `OPENAI_API_KEY` 安全填写到忽略的 `.env.local` 或运行环境设置；不要发到聊天或提交 Git，也不要使用 NEXT_PUBLIC 前缀。`OPENAI_MODEL` 默认 `gpt-4.1-mini`，管理员可指定兼容 Chat Completions 严格 JSON schema 的模型。修改后重启应用。

服务固定调用 `https://api.openai.com/v1/chat/completions`，没有自定义第三方代理 URL，没有新增 SDK。云环境需允许该域名，并在代理环境以 `NODE_USE_ENV_PROXY=1` 启动 Node.js 24；不绕过网络规则。没有 Key 的情况下不发送私人日记给模型。

供应商的留存、训练、地区和合约条件必须由项目负责人按当前账户条款核实。本次没有核实实时条款，不宣称零留存。API 设置 `store:false` 不等于消除供应商的所有留存；界面说明可能保留请求，测试请使用虚构事件。

## 接口与数据边界

`POST /api/ai/review`，JSON：

```json
{
  "entryId": "当前记录的 UUID",
  "expectedVersion": 1,
  "processingConsent": true
}
```

请求还需同源 Origin、真实会话 Cookie 和与会话一致的 `X-MemoNest-User`。这是既有服务端身份边界，不用客户端 user_id 代替认证。额外正文、owner、范围列表等字段被 strict schema 拒绝。

1. 服务端 `getUser()` 验证当前用户；未登录拒绝。
2. 从已有数据库读取指定记录，显式 owner、未删除过滤及 RLS，检查 expectedVersion；不接受浏览器提供的正文。
3. 只发送这一篇的标题、日期、正文，正文最多 6000 字符，不偷偷截断或检索其他记录。模型无保存、查询、授权工具。
4. 25 秒超时、900 输出 token 上限、64 KiB 响应流上限。模型需返回 1–3 个 `{text,quote}`，引用必须是正文的连续原句片段；截断、拒绝或无效输出不展示。
5. 生成后再次读取并核对当前记录版本/删除状态。改变即丢弃输出；这阻止生成期间的来源变化，不能抹去用户已经看过的内容。
6. 返回临时回顾与服务端来源 ID/版本/日期，响应 `private,no-store`。不写 JournalEntry、Memory、MemoryConsent，不记录正文/模型响应或凭据日志。

引用校验只能保证 quote 存在，**不能保证 text 的所有陈述忠实或模型理解正确**；仍需人工对照与效果评估。不把引用或 JSON schema 当作消除幻觉的证明。

进程内每用户最多一个在途请求、每分钟最多三次尝试，限制表最大 1000 项。这是开发阶段的基本防重复，不是跨实例可靠限流。公开服务前还需供应商预算/用量限制，必要时再部署共享限流；当前不新增复杂依赖或数据库迁移。

## 测试证据与未完成项

服务端契约测试用**显式模拟 provider transport**验证：缺 Key、单篇输入、store=false、无工具、响应/输入限额、无来源引用、截断、供应商失败/429、取消与进程限流。接口测试用显式认证/数据库夹具验证：owner 查询、未登录/未同意/跨 Origin 拒绝、旧版本拒绝、生成后编辑/删除丢弃。组件测试验证默认无许可、错误反馈、停止与迟到输出不显示、无 localStorage/原文修改。

以上都不证明真实 OpenAI 可用或内容质量。当前没有 Key，因此未运行真实模型生成；当前没有可完成邮箱确认的托管测试账号配置，真实登录与日记 E2E 也未完成。已有 `test:core:live` 仅用于真实本地 Supabase，不改变托管邮箱设置。不得把这些测试当成真实用户研究。

## 待实施效果评估

先建立 12 条人为编写并明确标注为虚构的单篇测试材料：具体事件、很短片段、情绪未明、否定、多个事件、敏感经历、注入指令、空信息等。材料尚未执行模型评测，不记成用户反馈。

| 维度 | 记录方式 | 初始放行规则（设计门槛，非结果） |
| --- | --- | --- |
| 来源忠实性 | 每条陈述对照正文，标注支持/推断/捏造；逐句查 quote | 任何捏造事实或跨来源内容阻止放行 |
| 处理范围理解 | 体验者复述发送范围、长期记忆与本次处理区别 | 严重授权误解先修复说明，不能仅看勾选率 |
| 回看价值 | 手动读原文 vs 回顾，任务“找出想重新看的具体片刻” | 能回到原文；无优势则降低回顾入口优先级 |
| 语气与控制感 | 记录冒犯、人格推断、医疗诊断、取消后感受 | 诊断、操纵性陪伴或强迫保存阻止放行 |
| 性能和成本 | 实际耗时、成功/超时次数、供应商 usage/费用 | 逐次记录；超时/失败不显示成功，预算超限关闭入口 |

先用虚构材料做负责人评审，再按已有 [用户研究计划](USER_RESEARCH.md) 和 [主持指南](USABILITY_TEST_GUIDE.md) 招募真实体验者。没有实际结果，不能写“AI 降低记录负担”“回顾提高留存”等结论。
