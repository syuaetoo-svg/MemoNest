# MemoNest：产品设计与全栈开发作品说明

这是基于仓库真实成果的求职展示材料，不是上线成功报告。产品研究尚处计划阶段，没有真实访谈、参与人数、业务效果数据或 Figma 成果。AI 回顾接口已开发，真实模型因缺 Key 未验收；托管账号/日记完整闭环也仍待实测。

## 一句话定位与用户价值

MemoNest 是以原创角色陪伴为入口的生活手帐：让用户记录愿意留下的经历，再通过时间线与可追溯回顾重新找到重要片刻。私人保存、角色长期记忆和单次 AI 处理分开，由用户决定范围。

目标用户是假设的成年年轻用户：愿意保留日常，但难以持续组织长文；需要轻量记录与找回内容，而非强制社交或关系打卡。尚未证明目标群体规模或需求强度。

## 核心痛点与证据边界

| 假设痛点 | 产品决策 | 如何验证 |
| --- | --- | --- |
| 写标题、整理正文增加记录负担 | 手动入口不依赖角色，标题可空，保存前预览；聊天为待验证路径 | E1 手动/脚本对话对照，记录总耗时与改错负担 |
| 保存经历被误解为 AI 永久记住 | 私人日记与精确摘要授权分实体，默认不授权 | E2 三种保存时机及复述题，观察错误授权/撤回理解 |
| 回顾好看却找不到真正想看的经历 | 时间线/关键词先行，AI 单篇回顾附逐段原文依据 | E3 找回任务与来源核对，比较完成情况而非仅满意度 |

这是设计假设与测试方案，不能用工程通过证明用户价值成立。竞品功能未核实的部分在 [竞品分析](COMPETITOR_ANALYSIS.md) 保持待验证，不把原创美术与关系机制照搬成差异化。

## 用户旅程及关键取舍

认识产品/原创小栖 → 可跳过角色直接记录 → 注册/确认/登录 → 写入/预览/私人保存 → 时间线找回 → 编辑/删除 → 可选授权精确摘要 → 可选同意单篇 AI 回顾。

优先级依据是先保证记录可靠、再验证 AI 增益：

- P0：真实身份、用户隔离、私人 CRUD/持久化、授权撤回；代码与迁移已有，真实托管验收未完成。
- P1：单篇有来源 AI 回顾，复用已有记录、版本与权限，不新增聊天数据库；代码完成，Key 与真实效果待验收。
- P2：真实用户研究、主题回顾与后续角色聊天；本次只整理已有研究计划，不扩展产品功能。

自动弹窗只在 UX Lab 研究；不为追求互动率强推保存。没有关系惩罚、默认全量记忆、自动 AI 改写原日记或模型直接操作数据库。

## 页面设计说明

| 页面 | 核心任务 | 体验与边界 |
| --- | --- | --- |
| 首页 | 理解价值与选择入口 | 暖白/鼠尾草绿，直接记录与原创角色入口并行 |
| 账号 | 注册、登录、退出 | 错误与邮箱确认状态清楚；身份切换清除旧客户端状态 |
| 角色介绍 | 认识小栖 | 原创设定，真实聊天仍禁用并解释，不展示假对话 |
| 记录编辑/详情 | 输入→预览→保存→修改/删除 | 保留失败草稿；幂等创建、版本冲突、删除二次确认与撤销窗口 |
| 记忆管理 | 找回原文与管理角色范围 | 时间线/关键词、分页、空状态；授权摘要可改/撤回，私人记录保留 |
| 单篇回顾 | 重新看见当前经历 | 当前来源/版本、供应商说明、非默认同意、停止、引用对照、临时结果 |
| UX Lab | 对照体验方案 | E1/E2/E3 八方案统一虚构素材，独立原型状态与匿名研究工具 |

手机优先，正文可换行、按钮最小点击高度、输入字号、键盘焦点和错误反馈沿用统一设计系统。桌面保留相同操作路径；自动化 viewport 检查不能当作实机软键盘、屏幕阅读器或真人体验测试。

## AI 设计与全栈落实

前端只发送记录 ID、预期版本及当次同意，服务端从真实用户所属的 PostgreSQL 记录读取内容，调用固定 OpenAI 接口。生成前后检查来源版本，回顾返回引用与来源，既不持久化结果也不扩大 MemoryConsent。缺 Key、响应无依据或超时都不显示成功；真实回复从供应商获取，没有写死的 fallback。

Next.js App Router + TypeScript + Tailwind CSS；Supabase Auth/SSR Cookie 管理身份，RLS 与受限 RPC 约束业务操作，服务端 getUser/Origin/操作账号再次校验。无需新增复杂依赖或数据库结构。详细流程、限额、取消边界与评估规则见 [AI 回顾说明](AI_REVIEW.md)。

## 面试展示顺序与可说/不可说

建议用 5–8 分钟介绍：用户假设与三道产品问题 → 手写/聊天取舍 → 私人记录/长期授权/单次处理三条边界 → 演示日记闭环 → 演示原型对照 → 说明 AI 来源校验与待验证价值 → 展示真实检查结果和剩余风险。

真实托管验收前，演示真实登录和 CRUD 必须标为待完成，不能用 UX Lab 的研究素材替代生产持久化。缺模型 Key 时只演示许可和诚实的错误反馈；不把 mock 测试输出录成真实 AI。

可以说“实现了可交互原型、服务端业务接口、权限迁移及自动化契约检查”；不可说“已验证降低记录成本、已服务若干用户、AI 效果提升若干百分比、完整上线”。真实验收后再把具体观察补进结果，失败也记录。

## 最小收尾计划

1. 在负责人可访问的开发环境完成两个受控邮箱的注册/登录及日记新增→刷新→编辑→刷新→删除→隔离验收，保留匿名结果清单。
2. 安全配置真实 AI Key 与预算/供应商政策说明，用虚构材料验证模型请求、引用忠实、取消及错误路径；未通过不宣称 AI 完成。
3. 用实际可操作页面录制简短演示，按研究计划收集第一轮真实观察；只更新已有方案与结果，不为求职展示继续堆功能。
